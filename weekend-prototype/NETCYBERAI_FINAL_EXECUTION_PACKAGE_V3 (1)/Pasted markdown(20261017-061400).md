## 2. ChatGPT's EXECUTION_PROMPT — verdict: strong skeleton, four real defects

**Keep (genuinely better than my v2):**

1. Truth-audit-first with a written `REPOSITORY_TRUTH_AUDIT.md` ledger and evidence paths — validated by the docs/12-vs-docs/17 contradiction above.
2. Worktree/branch discipline: separate clone, non-main branch, record base SHA, never touch Claude Code's active directory, deliver a commit/patch. More mergeable than my v2's "standalone folder + mock layer" pattern.
3. The 10-item `ANTIGRAVITY_HANDOFF.md` contract (SHA, files, migrations, tests with real results, security review, merge order, rollback).
4. `npm run typecheck / test / build / audit:seo` with "record actual output; never describe a failure as a pass."
5. RLS/security negative tests (unrelated-child fetch must fail), no-secrets-in-chat rule, `GAP:` marker convention.
6. "Benchmark before accuracy claims" for the grading assistant, and the crucial correction: **the Antigravity/Gemini subscription is a development entitlement, not a production runtime API key.** My package missed this.
7. Screenshot widths 390/1440, reduced-motion, EN/HI through the real i18n system.

**Correct:**

1. **Status misquote (§1 row 2):** it built its "the repo says not built" case partly on a history paragraph. The real conflict is README-vs-code and docs/12-vs-docs/17 — which is still enough to justify the audit, but the audit prompt must tell the agent to read the *current status block* and treat labelled history as history.
2. **Wrong filename** for docs/31 (see §1) and it told the agent to "synthesize a fresh spec" if the file is missing — with the right filename the file resolves; that instruction would have manufactured a false gap.
3. **Scope overreach:** Stages 2–9 are effectively the entire roadmap (family app, vault, WhatsApp/Meta, Automation OS, AI router, Acadine ×4, LoiLo ×6, trust dashboard). In one weekend, against a quota that renews Sunday 11:30, with Sunday needing review budget, this guarantees shallow work or a stalled session. No cut order, no timebox.
4. **It lets the agent build Automation OS and the AI router** — the two components deepest in the repo's contracts and the worst possible things to parallel-build. These must be out of scope.

**Missing:**

1. My Automation Blueprint (node map, 10 packs, edge table, simulations) is not in its attachment list — so its Stage 5/6 reinvents the automation architecture from scratch instead of implementing the agreed design.
2. The WhatsApp-only acceptance rule (Eneza pattern): every family-facing feature must be provably usable with zero app opens. Not required as a test anywhere.
3. A per-workstream feasibility gate with a stop-and-report rule before touching contract-heavy areas (it has a first-response report, then proceeds unconditionally).
4. The ease-and-colour standard is name-checked but its concrete rules (which my blueprint and docs/19 carry) aren't wired into acceptance criteria.

## 5. Self-critique — my own files, judged by the same standard

1. **My master plan repeated docs-based statuses without code evidence** (e.g. "Teacher App P2 largely built/tested" from docs/20; teacher routes verified today live inside `(school)/app`, not a standalone PWA). The plan's own Challenge Rule already says code outranks documents — but the plan should have flagged *itself* as unverified at code level. It does, weakly. The truth-audit step now makes this the audit's job, which is the right resolution.
2. **My v2's standalone-folder + mock-service-layer pattern is inferior for mergeability.** Building in a proper worktree branch on the real stack (ChatGPT's approach) produces patches Claude Code can review and apply directly; my pattern produces a parallel codebase needing translation. I keep the mock/demo-layer idea only where the repo docs call for labelled demo surfaces.
3. **My v2 lacked:** the 10-item handoff contract, dependency map, npm-script verification, screenshot-width matrix, benchmark-before-claims, and the dev-entitlement-vs-runtime-key warning.
4. **My status labels in v2** (Homework "Planned", etc.) came from docs/17, which docs/12 contradicts. Lesson: no document, mine included, gets to assert status. The audit ledger is the only source.
5. **My blueprint stands** as the automation design (packs, gates, edge table, simulations) — but its §11 must be re-stated as design-to-be-reconciled, not an implementation order, until the truth audit passes.
